Module 3 · 9.5
Security: three routing attacks

Wormhole

Record packets at one place, tunnel via fast private link, replay elsewhere → false short path, misrouting

Sybil

One attacker, many fake identities → undue influence on voting, resource allocation, routing

Rushing

Forwards RREQ very fast → its copy arrives first, legit copies dropped as duplicates → interception / partition

Module 3 · 9.6
Data sensing & collection models

Time-driven

Regular intervals, changed or not.
Smart-grid PMUs at fixed rate

Event-driven

Only when an event occurs.
ITS alert when jam detected

Query-driven

Only on request.
"Temperature of zone 3 now?"

Hybrid

Mix of models.
time-driven → event-driven when special

Impact on routing: energy (how often & how much) · route stability (varying rates)
Module 3 · 9.7–9.8
Scalability & QoS

Scalability

Huge numbers of sensors; efficient at any size.
• Dynamic response: join/leave/sleep
• Energy mgmt: route via awake nodes
• Event-driven: many nodes active at once (fire, intrusion)

QoS — bounded latency

Late data = useless data.
• ITS: speed drops sharply (jam) → send immediately
• Prefer low-latency routes
• Prioritise critical data
