Module 3 · 11 · 11.5
GPSR — Greedy Perimeter Stateless Routing

Mode 1 · Greedy (primary)

While a neighbour closer to D exists

Mode 2 · Perimeter (fallback)

At a local minimum: planar graph + right-hand rule

Reached a node closer than where greedy failed? → switch back to greedy. Solves local minimum, keeps greedy's efficiency.
Module 3 · 11 · 11.6
GEAR — Geography & Energy-Aware Routing
Dual criteria: distance to destination + residual energy
Avoid overusing low-energy nodes; composite metric, prefer higher energy
cost = α · (norm. distance) + (1 − α) · (norm. energy used) → choose min (illustration, not on slides)

Benefits

Load distribution, no bottlenecks, longer lifetime

When greedy fails

Recursive geographic forwarding · restricted flooding

Module 3 · 11 · 11.7
WEAR — Wear-Evidence-Aware Routing

Hole detection

Exchange location + activity; sparse area = hole; edge nodes = boundary nodes

Broadcast

Hole info via controlled flooding → low overhead

4 decision factors

distance · energy · location · local hole info

Benefits: hole avoidance · load balancing · fault tolerance (new holes)
Module 3 · 11 · 11.8
GAF — Geographical Adaptive Fidelity
Virtual grid: nodes in one cell are equivalent — any can reach any node in adjacent cells

Sleep

Radio off; others keep the cell connected

Discovery

Wake periodically, find cell neighbours, decide active/sleep

Active

Routes; one active node per cell

Discovery → Active (chosen) / Sleep (another active) · Active → Discovery (time over) · Sleep → Discovery (timer)
4 nodes per cell, 1 awake → each awake ~25% → lifetime ≈ 4×

GREES — Environmental Energy Supply

1 · Geo + energy

Proximity & route energy efficiency

2 · Real channels

Attenuation, interference, varying links

3 · Packet advance

Big progress per hop → fewer hops

4 · Residual energy

High-energy nodes preferred

5 · Harvesting

Solar-powered nodes preferred ☀

Realistic model · load balancing · longer lifetime. Sunny day: solar node chosen over battery-only node at similar distance.
Module 3 · 11 · 11.10–11.11
BOSS & EBGRES — beaconless
Problem: periodic beacons for neighbour tables = big overhead → BOSS: the DATA message is the probe
Adapts to mobility & link changes (probes every transmission) · efficient · real-time · less congestion

EBGRES

Like BOSS: beaconless, fewer control messages, uses DATA · ACK · SELECT — plus considers environmental energy (solar) → energy-harvesting networks
